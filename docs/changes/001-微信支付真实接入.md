# [001] 微信支付真实流程接入（mock 开关 + APIv3 占位）

- 日期：2026-10-13
- 状态：已完成
- 涉及端：server / admin / miniapp
- 关联文档：[docs/API.md](../API.md)（支付接口与 17 个订单字段）

## 需求点

- 接入**真实完整的微信支付流程代码**，但 Demo 不能依赖真实商户号也能跑 → 提供 mock 开关，占位配置后续替换即可切真通道。
- 退款运营侧要**带金额**操作（弹窗输入金额 + 原因）。

## 改动明细

| 端 | 文件/目录 | 改动内容 |
|---|---|---|
| server | `src/util/wechatpay.ts` | 新增：APIv3 全套真实实现——JSAPI 下单、商户 RSA 私钥签名、回调验签 + AES-256-GCM 解密、退款申请（mTLS）、`code2session` 换 openid；用 Node 内置 `crypto`，零新依赖 |
| server | `src/config/config.default.ts` | `WXPAY_PLACEHOLDERS` 8 项占位清单 + `validatePayConfig()` 启动校验（PAY_MOCK=0 时占位未替换则拒绝启动并列明缺项） |
| server | `src/app/service/pay.service.ts` | 支付下单/状态确认/退款逻辑，`PAY_MOCK=1` 直接置 paid |
| server | `.env` | `PAY_MOCK=1`（默认）、`PAY_STRICT=1`（是否强制未支付禁派单/抢单）、`WXPAY_*` 8 项占位 |
| miniapp | `pages/order-detail/order-detail.js` | 「去支付」：`wx.login` 换 code → `/api/pay/params` → `wx.requestPayment` → 轮询支付确认 |
| admin | `views/order/*` | 订单列表支付列 + 徽标；详情带金额退款弹窗（`/api/admin/order/:id/refund` body `{amount, reason}`） |

## 关键决策

- **`PAY_MOCK=1`（默认）**：不填商户号也能全链路演示；`PAY_MOCK=0` 才走真实 APIv3。
- 8 项占位（mchid / serial_no / APIv3 密钥 / 商户私钥 / appid 等）放 `server/.env`，替换后即切真通道，**代码零改动**。
- `PAY_STRICT=1` 时未支付订单禁止派单/抢单（403）；默认关闭方便演示。

## 验证记录

- `scripts/api-test.sh` 含 **17 项支付用例**（下单/支付/回调/退款/幂等），73/73 全绿。

## 使用说明

- 演示直接用默认 mock；切真实支付：`server/.env` 填 8 项 `WXPAY_*` + `PAY_MOCK=0`，重启服务端。
- 详见 README「常见问题」WXPAY 占位说明。
