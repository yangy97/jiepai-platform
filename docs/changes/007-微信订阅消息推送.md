# [007] 微信订阅消息推送（小程序能力触达微信侧通知）

- 日期：2026-10-14
- 状态：已完成
- 涉及端：server / miniapp
- 关联文档：docs/API.md「订阅消息推送」、docs/changes/002（站内通知体系）

## 需求点

用户诉求（原话大意）：

> 这个通知是怎么发送？通过微信推送吗？我希望的是在**微信小程序的能力**推送对应的消息（我记得是需要微信授权什么的）。

背景澄清：

- 现状通知是**纯站内信**：`notification.service.notify()` 只往 `notifications` 表写一行，小程序靠「消息中心」页拉取 + 未读角标，**不会触达微信侧**。
- 用户记忆中的「微信授权」= **订阅消息（subscribe message）授权弹窗**：小程序调 `wx.requestSubscribeMessage`，用户点「允许」才获得推送资格。

目标：接入微信小程序**订阅消息**推送——真实 API 全代码 + 占位配置（沿用 001 支付的模式），默认 mock 可跑通；失败静默降级回站内信，绝不阻断业务主流程。

## 关键决策

- **一次性订阅语义**（普通类目小程序只有这一种）：每授权 1 次 = 每个模板可推 1 条；发送时未授权返回 `43101` → 静默跳过（站内信兜底）。长期订阅仅政务/医疗等特殊类目可用，不适用本项目。
- **授权时机必须由用户 tap 触发**（微信平台规范）：挂在登录/注册按钮与「消息中心」入口的点击回调首行，不自动轮询弹窗。
- **openid 来源**：接收方 `users.openid`（登录成功后 `wx.login` code 走既有 `code2session` 写入；支付流程会复用同一字段）。为空则跳过推送。
- **模板 ID 是占位的**：需在 mp.weixin.qq.com 后台「订阅消息」选用模板并通过审核后，把真实 ID 填入 `.env`（服务端）与 `miniapp/config.js`（客户端弹窗用），两处必须一致。
- **模板字段 key 不通用**：每个模板的字段（thing1/time2/amount3…）序号各异，`SUBSCRIBE_TEMPLATE_FIELDS` 是唯一调整点。
- **mock 默认**（`SUBSCRIBE_MOCK=1`，与 `PAY_MOCK` 同款）：落库照常、推送打 MOCK 日志；真实通道 = `SUBSCRIBE_MOCK=0` + 真实模板 ID + 真实 `WXPAY_APPID/SECRET` + 用户已授权。
- **access_token 进程内缓存**（7200s，提前 5 分钟过期）：Demo 单进程足够；多实例部署需换集中缓存（如 Redis）。

## 使用说明

**演示默认（零资质）**：什么都不用配。`SUBSCRIBE_MOCK=1`（默认）下每次通知都打 `[subscribe] MOCK推送` 日志；小程序 `SUBSCRIBE_TMPL_IDS=[]` 不弹授权窗，通知全部走站内信，全流程照常跑通。

**启用真实推送（四步）**：

1. mp.weixin.qq.com 后台「订阅消息」选用/申请模板并过审核，拿到 Template ID（5 类：派单/完工/退款/取消/上门提醒）。
2. `server/.env` 填 `WX_TMPL_DISPATCH` 等真实 ID（与已有 `WXPAY_APPID/SECRET` 共用小程序凭证），并设 `SUBSCRIBE_MOCK=0` —— 启动时 `validateSubscribeConfig` 校验，缺失/占位直接报错拒启。
3. `miniapp/config.js` 的 `SUBSCRIBE_TMPL_IDS` 填同一批真实 ID（两处必须一致），重新编译小程序。
4. 模板字段 key 按所选模板调整 `server/src/constant/notification.constant.ts` 的 `SUBSCRIBE_TEMPLATE_FIELDS`（每个模板的 thing/time 序号不同）。

用户在登录/注册或「我的 → 消息中心」点击时弹授权（每授权 1 次 = 每模板 1 条额度）；发送时未授权（`43101`）自动降级站内信，仅 warn 不影响业务。
