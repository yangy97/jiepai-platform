# [005] 三端常量与工具分层规范（常量归 constants/、工具归 util/）

- 日期：2026-10-13
- 状态：已完成
- 涉及端：server / admin / miniapp

## 需求点

- 用户诉求原话：「开发尽量规范一点，如果是常量最好用一个文件夹装常量文件，包括小程序和 admin 和 service 都要这样做；如果是工具方法就用 util 这样的来做区分」。
- 目标：三端统一「**纯数据常量 → `constants/`（server 为 `constant/`）；纯函数 → `util/`**」，行为零变化。

## 关键决策

- **值一字不改、只搬家**：中文注释随定义迁移；三端常量文案保持三端一致。
- **保留原地的**：`config/config.default.ts` 的 `WXPAY_PLACEHOLDERS`（配置校验私有常量，config/ 即专属归处）；各页面自己的 `PAGE_SIZE`（页面级分页配置，就近原则，非共享常量）；`miniapp/config.js`（全局配置文件，非纯常量模块）。
- miniapp `order-list.js` 的 `STATUS_TABS` require 一并改道（该常量移出 format 后不再导出，不动会 `undefined`）——迁移时注意此类连带消费方。
- 引用路径显式写全 `constants/index`（小程序无目录解析依赖）。

## 使用说明

- 之后加状态/文案/标签类常量，一律进对应端的 constants 目录，不在页面/service 内联大写对象。
- 三端对应关系：`server/src/constant/`、`admin/src/constants/`、`miniapp/constants/index.js`。
