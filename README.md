# 接派 · 上门服务接单派单平台

参考「55飞手」类接单小程序的业务形态，面向**技能上门服务**（家电清洗、管道疏通、家具安装、保洁…）的完整接单/派单 Demo：客户在微信小程序发单，运营在 Web 管理端派单，师傅在小程序抢单接单并完成结算。

```
jiepai-platform/
├── miniapp/     微信原生小程序（客户端 + 师傅端）
├── admin/       Web 管理端（Vue3 + TS + Element Plus，风格参照 futucode/oa_template）
├── server/      服务端（TypeScript + Express + MySQL + JWT，三端共用，tsx 直跑无需编译）
├── docs/        接口契约 / 设计蓝本 / 变更需求点记录（CHANGELOG 索引）
└── scripts/     dev 启动脚本 + API 冒烟测试（基础 73 项 + 阶段二 39 项）
```

## 角色与流程

| 角色 | 入口 | 能做什么 |
|---|---|---|
| 客户 | 小程序 | 选类目（一口价/时薪、退款政策下单锁定）→ 填需求下单 → 支付 → 等待接单 → 确认完成 → 多维评价 / 取消（自动按政策退款） |
| 师傅 | 小程序 | 入驻认证 → 抢单/接受派单 → 开始服务 → 完工或中途退出（按时长结算）→ 钱包入账 → 回评客户 |
| 运营 | Web 管理端 | 派单/改派、代操作状态、手动退款（带金额）、审核师傅、类目 CRUD、消息铃铛、受限账号解除、数据看板 |

订单状态机：`pending 待接单 → dispatched 已派单 → accepted 已接单 → working 服务中 → finished 待确认 → completed 已完成`（任意非终态可 → `cancelled`；`working → aborted 中途结束 → completed` 按实收结算）。

## 环境要求

- **Node.js 18+**（项目锁定 20：`nvm use`）
- **MySQL 8/9**（本机已在跑，`mysql -uroot` 免密可连）
- 微信开发者工具（仅小程序可视化调试需要）

## 一、初始化数据库

```bash
cd jiepai-platform
npm run db:setup        # 建库建表 + 种子数据（等价 server 的 db:init + db:seed）
```

库名 `jiepai_platform`，连接信息在 `server/.env`（默认 `root@127.0.0.1:3306`，无密码）。

## 二、启动服务端 + 管理端

```bash
nvm use                 # Node 20
cd server && npm install && cd ..
cd admin  && npm install && cd ..
npm run dev             # 并行启动 后端 7010 + 管理端 5178
```

- 服务端 API：<http://127.0.0.1:7010/api/health>
- 管理端：<http://localhost:5178/>（`/api` 已由 Vite 代理到 7010）
- 首次或数据乱了：`RESET_DB=1 npm run dev`（重置库再启动）

## 三、打开小程序

微信开发者工具 → 导入项目 → 目录选 `jiepai-platform/miniapp`（AppID 用测试号/游客模式即可）。
小程序请求地址在 `miniapp/config.js` 的 `BASE_URL`，默认 `http://127.0.0.1:7010`。
> 本地调试请在开发者工具「详情 → 本地设置」勾选 **不校验合法域名**。

## 技术要点

- **服务端 TypeScript**：全量 TS（strict）+ `tsx` 直跑免编译，`npm run typecheck` 类型检查；DB 行类型 / 泛型查询 / 请求上下文均有类型定义。
- **统一响应**：`{code, message, data}`，`code=0` 成功，HTTP 状态码同步；错误处理中间件集中兜底。
- **鉴权**：JWT（`Authorization: Bearer`），`authRequired` / `requireRole('admin')` 中间件分级挂载。
- **微信支付 APIv3**：RSA2048 商户签名、平台证书回调验签、AES-256-GCM 解密、退款 mTLS、code2session 换 openid——全部 Node 内置 crypto 实现，零新增依赖；`PAY_MOCK` 开关双通道。
- **并发抢单**：`UPDATE ... WHERE status IN (...)` 乐观锁，`affectedRows=0` 返回 409，杜绝重复接单。
- **结算事务**：确认完成时在事务内完成 `钱包入账 + 流水 + 师傅完成量 +1`，失败自动回滚；中途结束按 `actual_fee` 结算。
- **管理端风格**：深色侧边栏（#001529）+ 路由 `meta.isMenu/text/icon` 驱动菜单 + 递归 SubMenu + 面包屑顶栏，与 `futucode/oa_template` 一致；后端沿用其 `app/router + controller + service` 分层约定（内部 Egg 框架不可用，改用 Express 复刻）。

## 常见问题

| 现象 | 处理 |
|---|---|
| `ECONNREFUSED 3306` | `brew services start mysql` |
| 表不存在 / 数据乱了 | `npm run db:reset` |
| 管理端接口 401 | 先起服务端；或退出重新登录 |
| 小程序请求失败 | 检查 `miniapp/config.js` 的 `BASE_URL`，勾选「不校验合法域名」 |
| 端口被占 | 改 `server/.env` 的 `PORT`，同步改 `admin/vite.config.ts` 代理 |
| 服务端启动报 WXPAY 配置占位 | 正常：`PAY_MOCK=0` 走真实微信支付前需填齐 `.env` 里 8 项 `WXPAY_*` 真实值；Demo 保持 `PAY_MOCK=1` 即可 |
